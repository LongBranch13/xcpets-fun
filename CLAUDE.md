# XCPETS – notes for Claude

## What it is
XCPETS is an on-chain pet game on Bitcoin/Counterparty. Players burn XCPETS tokens with text tags (e.g. `pet:hatch`, `pet:breed:A:B`, `pet:feed:ID`); the game state is rebuilt by replaying every burn from the chain in order. Site: https://xcpets.fun (GitHub Pages). Repo: https://github.com/LongBranch13/xcpets-fun (deploy = merge to main; Pages publishes in ~1-3 min).

## Rules
1. Never sign burns or transactions. Never handle wallet keys.
2. Never put secrets, the node's onion address or server connection details in code, commits or public posts.

- `rjs/*`: the frozen engine for burns up to block 971,500. `rjs/chain.js` reads block hashes. It requires a trusted source or two agreeing sources plus a proof-of-work check (PR #88).
- Rules signature (rsig): a hash of the rule files (incl. `js/v2-rules.js` and `rjs/chain.js`). Changing any of them changes the rsig.
- World snapshot: a pre-built world served at `https://node.xcpets.fun/xp/v1/world/latest.json` (+ slim view files: `view/summary.json`, `owners.json`, `rank.json`, `p/000NN.json` shards, `own/<sha256(addr)>.json`). Browsers use it only if its rsig matches the page's rules, otherwise they replay locally (slow). It is built by the sync server itself on the VPS (`tools/sync-server`, every 6 blocks, from the rule files on the VPS disk). **After any rules or rsig change, the VPS copy of the repo must be updated too**, or players fall back to the slow load.
- node.xcpets.fun: a Hetzner VPS running the sync server (`/opt/xcpets-sync`, service `xcpets-sync`) and a node cache, backed by the game's own Counterparty node. Access comes from the owner; never publish its details.
- Feed: `api/boot.json`, `meta.json`, `pets.json` are rebuilt by a game-server timer about every 20-25 min.
- Never-freeze layer (Nov 24, 2026): stalled-body timeouts in `tools/sync-server/net.js` and `tools/lib/core-limiter.js`, a stall guard (exit 70 after 10 min), saved follower state, a health heartbeat (`loop`), an on-server watchdog (server-repair `sync_watchdog`), HatchBot server alerts (`hatchbot/serverwatch.js`, `/alerts`, `/status`) and worldwatch auto-reboot after 25 min. See `tools/sync-server/README.md` "Never freeze". Changes to the service process itself (`index.js`, `net.js`) reach the VPS only through a server-repair run.
- World copy (Nov 25, 2026): GitHub builds the same world (`tools/world-copy.js`, workflow `world-copy`) into a Cloudflare R2 copy (`cloud/world/worker.js`, bucket `xcpets-world`); `sw.js` gives pages the copy's `latest.json` when the server is down, errors or is 6+ blocks behind (`COPY` in sw.js; empty = off). Burns still need the server. See `tools/sync-server/README.md`.
- Workers (`js/v2-verify-worker.js`, `v2-catchup-worker.js`, `v2-resume-worker.js`) fetch the rules as text, patch them with strings, then eval them. They're fragile, so be careful when reformatting `v2-rules.js`.

## How to verify a deploy
- Compare the MD5 of each changed live file (`https://xcpets.fun/<file>?cb=<random>`) with raw main.
- Check that `js/v2-rules.js` MD5 is what you expect.
- If rules or rsig changed: confirm `latest.json` shows the new rsig and a current tip.

## Tests
`tools/*-test.js` (node), run by `node tools/run-tests` (workflow `tests`): 600 s per test file, `--jobs 4`, known failures in `tools/fixtures/known-failures.txt`. Keep it green; if a test fails, fix the cause, never the test's reach.
- **Rule-file MD5s live in one place**: `tools/fixtures/rules-pin.json`, read through `require('./lib/rules-pin').pin('js/v2-rules.js')`. After a reviewed rules change run `node tools/rules-pin-test.js --write` (it also checks CLAUDE.md's "Current MD5" above). Never paste a hash into a test again: 26 tests used to hold their own copy and every rules PR turned them all red.
- **Don't pin source text or `?v=` tokens.** Run the real function with stubs, or check the thing itself (sw.js's version is read from sw.js, a cache token only has to be present). Those pins broke on every later edit while the behaviour was fine. `tools/stale-pin-guard-test.js` fails if one comes back (`stale-pin-ok` on the line, with a reason, for a pin that is meant).
- **Fixtures age**: pick pets the 14-day dead-pet rule keeps (`V.retireDeadDue`), pets a burn can really name (`V.spinList`), and step cooldowns with `V.spanAt` (the downtime pause).
- **Slow tests**: `tools/lib/fork-replay.js` replays `api/boot.json` once and branches each scenario off that checkpoint (~5 s instead of ~60 s). Its patch anchors must match `js/v2-rules.js` exactly once or it throws: a moved line once made every "forked" replay a full one and four tests crept to the limit. `resume-equiv` is split into four files (snap fixtures, live, back, tip) for the same reason.

## The fast-load layer (where most bugs live)
Pages paint from a slim "fast world" (js/v2-split.js assemble, js/v2-art.js, the verify/catch-up workers) instead of a full replay. It is missing parts of the full world (listings, swaps, quests, most of w.cem, rules' in-memory switches). Bugs found Nov 22, 2026 were all here: missing w.cem.altars (seance button), v2-art.js not exporting self.XcpArt in workers (every pre-sign owner check failed), gear/hatch "new" detection running on a half-loaded list, rules pool switches never set (FUNTRUMP breeding). Never fix these by editing the rules.
- Fast world state (Nov 25, 2026): every top-level rules table now rides in the view's `summary.state` by default (`tools/sync-server/split.js` STATE_OWN / STATE_SKIP / STATE_SLIM; `js/v2-split.js` assemble copies it onto the world, a fresh copy per world). A new rules table needs nothing; skipping one needs a reason in STATE_SKIP. `node tools/fast-world-state-test.js` fails if a page (or a rules function a page calls) reads a skipped table, and `node --max-old-space-size=9000 tools/fast-world-audit.js` replays the real chain and compares 33 rules answers on the full vs the fast world.
- **tools/fastcheck** (workflow `fastcheck`, manual + every 6 h) loads real wallets on the live site in view-only mode, replays the full game to the same block and lists every difference (pets, gear, before-signing checks). Run it after any change to the loader.
- View-only testing: set localStorage `xcpets-v2-me` to an address (no wallet, nothing can be signed). Clean it up afterwards.
- Hatch reveals (Nov 25, 2026): the verify worker's 'mine' list leaves out art only for pets the page already had in the published world; new hatches carry it (a missing art crashed the reveal after the eggs were marked seen). New eggs also sit in an 'unopened' list (localStorage `xcpets-v2-unopened-*`) until their review is closed, so a missed pop-up comes back as the pill; My Pets has "🥚 Last hatch". Fast check `node tools/hatch-unopened-test.js`; full flow at real scale (3 Shock Boxes in one block, Later, reload, pill, Select all, Discard, Undo) `node --max-old-space-size=9000 tools/hatch-flow-e2e.js` (~5 min, Playwright).
